我的阅读进度

适合谁

两类读者共用同一份正文：正文讲原理，章末给话术。

🌱初学者

按顺序读完「主线」四章。目标是理解，不是记忆。K8s 的核心概念其实很少，对象只是同一套思想在不同场景下的具体化——这个项目先给你思想，再带你看对象。

🎯面试者

直接跳各章末尾的「面试官视角」与「常见误区」。理解力和表达力是两回事，很多人懂但答得平庸——这里给出「烂大街答案 vs 加分答案」的对照。

写作约定

每章固定结构，术语跟随中文社区实际语感。

🧱每章的固定结构

一句话答案（30 秒版）→ 为什么需要它（动机）→ 核心概念（原理）→ 怎么工作（机制 + 图）→ 面试官视角 → 常见误区 → 延伸（指向官方文档，不在此展开）。

🈶术语处理

中文为主、括号标英文：节点（Node）、调度器（Scheduler）；社区惯用英文的保留英文：Pod、Deployment、Service；组件名直接用：kubelet、etcd、kube-proxy。Pod 官方译名「容器组」几乎无人使用，故从社区习惯。
